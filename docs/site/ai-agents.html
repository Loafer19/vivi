Control Vivi from AI agents

vivi-mcp is a tiny Model Context Protocol server that lets Claude, Cursor, VS Code and other MCP clients play, search, queue and inspect media in a running Vivi.

Set it up All 26 tools

What it is

A separate small binary that speaks MCP over stdio and forwards tool calls to Vivi through a private local socket. The player only adds a tiny socket listener; vivi-mcp depends on nothing but std and serde_json. There is no network listener and nothing leaves your machine.

AI client (Claude Desktop, Cursor, …) ──stdio / JSON-RPC──▶ vivi-mcp ──Unix socket / JSON lines──▶ Vivi

Set up in two minutes

1. Enable remote control in Vivi

It is off by default. Turn on Settings → General → Remote control → Allow AI agents and scripts and restart Vivi, or start it once with VIVI_IPC=1 vivi.

2. Get vivi-mcp

It ships with Vivi: the Arch package installs /usr/bin/vivi-mcp, the Flatpak /app/bin/vivi-mcp, and cargo build --release produces target/release/vivi-mcp. Run vivi-mcp --help to see the socket path it will use.

3. Add it to your client

Claude Desktop

~/.config/Claude/claude_desktop_config.json (macOS: ~/Library/Application Support/Claude/)

{
  "mcpServers": {
    "vivi": { "command": "/usr/bin/vivi-mcp" }
  }
}

Cursor

~/.cursor/mcp.json, or .cursor/mcp.json in a project

{
  "mcpServers": {
    "vivi": { "command": "vivi-mcp", "args": [] }
  }
}

Claude Code

One command, available in every session:

claude mcp add vivi -- vivi-mcp

VS Code / GitHub Copilot

.vscode/mcp.json

{
  "servers": {
    "vivi": { "type": "stdio", "command": "vivi-mcp" }
  }
}

Windsurf, Zed, Continue, Cline, … any client that launches stdio servers works with command: vivi-mcp. Flatpak: use "command": "flatpak", "args": ["run", "--command=vivi-mcp", "io.github.loafer19.vivi"].

IPTV and radio: open also plays URLs, but open_network_stream validates the URL, can queue instead of replacing, and shows a station name. A whole .m3u playlist URL can be passed to open (mpv expands it into the queue).

Security

Off by default. Nothing listens until you enable Remote control.
Local only. The socket is $XDG_RUNTIME_DIR/vivi.sock (fallback ~/.cache/vivi/vivi.sock, override with VIVI_SOCKET), created with mode 0600, so only your user can connect. There is no TCP or HTTP listener.
Limited reach. Agents can control playback and read what is playing; plugin tools are read-only and plugin settings cannot be changed. Anything an agent opens plays with your user's permissions, so keep the usual care with untrusted URLs.

Troubleshooting

“Vivi is not running” or connection refused
Start Vivi with Remote control enabled (restart after changing the setting) or run VIVI_IPC=1 vivi. Only one Vivi instance owns the socket.
The client cannot find the socket
Some clients do not inherit XDG_RUNTIME_DIR. Pass it explicitly: "env": { "VIVI_SOCKET": "/run/user/1000/vivi.sock" } (check the path with vivi-mcp --help).
“command not found: vivi-mcp”
Use the absolute path (/usr/bin/vivi-mcp or target/release/vivi-mcp); GUI clients often have a minimal PATH.
Test without an AI client
npx @modelcontextprotocol/inspector vivi-mcp, or by hand: 
printf '%s\n' '{"jsonrpc":"2.0","id":1,"method":"tools/call","params":{"name":"get_status","arguments":{}}}' | vivi-mcp
echo '{"cmd":"status"}' | socat - UNIX-CONNECT:$XDG_RUNTIME_DIR/vivi.sock
search_streams is slow or empty
It queries radio-browser.info and iptv-org over the network and can take a few seconds.
Windows
Not supported yet: the control socket is a Unix socket (Linux and macOS). Only the stdio transport is available.
