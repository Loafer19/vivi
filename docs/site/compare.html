Where the others win

mpv

Smaller on disk and lighter when idle than Vivi in our measurement, with a huge collection of user scripts and the most configurable video output. Vivi itself is built on libmpv.

VLC

Lowest idle memory and fastest start in our test, runs on nearly every platform including mobile, and plays discs and devices that Vivi does not target.

foobar2000

Long audio-focused polish: gapless playback, ReplayGain, CD ripping, transcoding, DSP effects and a large component ecosystem. Not open source, and no video.

IINA

A truly native macOS app with trackpad gestures, Picture in Picture and Live Text. Vivi's macOS build is unsigned and best effort.

MPC-HC

A mature Windows classic built on the DirectShow / LAV filter ecosystem.

Celluloid

Opens its window slightly faster than Vivi from a cold cache in our test (~0.73 s against ~0.77 s; warm, Vivi is a little ahead at ~0.33 s against ~0.35 s), fits right into GNOME with GTK, MPRIS and Wayland support, and reads your existing mpv config files as-is.

How we measured

Size was measured on 27 Oct 2026 (v0.15.0); start time, memory and CPU on one desktop under identical conditions on 18 Oct 2026. Numbers appear only where we measured them.

  • Download: size of vivi-v0.15.0-linux-x86_64.tar.gz on the GitHub release (18,797,256 bytes). mpv and VLC on Linux come from distribution packages, so there is no single download to compare.
  • Installed size: Vivi = the files the installer copies (vivi, vivi-mcp, desktop file and icons), excluding the system libmpv. mpv and VLC = the Installed-Size of their Debian 13 packages (mpv + libmpv2; vlc, vlc-bin, vlc-plugin-base, vlc-plugin-qt, libvlc5, libvlccore9), excluding shared libraries such as FFmpeg and Qt. Celluloid = the Installed Size of the Arch Linux package celluloid 0.30-2 (1,191 KiB, measured 18 Oct 2026), excluding libmpv and GTK.
  • Start time, memory and CPU: Arch Linux, Hyprland (Wayland), NVIDIA RTX 3060 Ti, 12-core CPU, 16 GB RAM; each player with its normal configuration on that PC. Vivi = the v0.12.0 release (Linux tarball, installed as the Arch vivi-bin package), mpv 0.41 (--idle --force-window=yes), VLC 3.0.23 (Qt interface), Celluloid 0.30 (GTK 4, on the same libmpv 0.41, default settings). Time runs from launch to the first Wayland surface attach (WAYLAND_DEBUG=1, polled every 20 ms); VLC 3 draws through XWayland, so for VLC it is the time until its window is mapped (hyprctl clients). Warm = median of 3 runs; cold = after echo 3 > /proc/sys/vm/drop_caches. Memory is PSS of the main process from /proc/PID/smaps_rollup 3 s after the window appears, idle (nothing opened) or playing a local 1080p H.264 clip (1080×1920, 30 fps); CPU is the average over 10 s of that playback (100% = one core). Vivi and VLC decode on the GPU there; mpv and Celluloid use software decoding unless hwdec is set. Celluloid playing memory is the mean of 2 runs (531 and 604 MB).
  • MPC-HC, IINA and foobar2000 do not run natively on Linux, so no numbers are shown for them.
